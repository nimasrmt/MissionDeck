# اتصال API و مدل‌های شخصی

در صفحهٔ تیم‌ها، دکمهٔ **API & my models** را باز کنید. برای هر مدل یک اتصال بسازید: نام دلخواه، قالب API، Base URL، شناسهٔ دقیق مدل و کلید. قالب‌های پشتیبانی‌شده OpenAI-compatible Chat Completions و Anthropic Messages هستند؛ APIهای فقط Responses یا Gemini بومی باید از درگاه سازگار استفاده کنند.

## ذخیره، آزمون و انتخاب

۱. **Save connection** فقط اطلاعات را محلی ذخیره می‌کند و درخواست مدل نمی‌فرستد.

۲. **Test & enable** یک درخواست کوچک با حداکثر ۱۲۸ توکن خروجی برای آزمون tool call می‌فرستد و وجود همان مدل را در کاتالوگ پروژهٔ OpenCode بررسی می‌کند. این آزمون از حساب API خودتان استفاده می‌کند؛ رایگان‌بودن یا ظرفیت باقی‌مانده را اثبات نمی‌کند. پاسخ عادیِ متنی بدون tool call برای اجرای عامل کافی نیست.

۳. در تنظیمات هر نقش، **Browse AI images and models → My API models**، مدل آزموده‌شده را انتخاب کنید. **Use for new AI roles** نیز آن را به انتخاب پیش‌فرض نقش‌های جدید تبدیل می‌کند؛ نقش‌های قبلی مدل خود را حفظ می‌کنند. انتخاب یک مدل رایگان، پیش‌فرض API را کنار می‌گذارد.

۴. چت با منیجر یا شروع مأموریت، اقدام مستقل کاربر است. بازکردن صفحه، بارگذاری مجدد، دیدن کاتالوگ و ذخیرهٔ اتصال، inference اجرا نمی‌کند. مدل API از همان مسیر اجرای native Orca/OpenCode و سقف دو نشست استفاده می‌کند؛ مدل دیگری به‌صورت fallback انتخاب نمی‌شود.

## نگهداری کلید و تنظیمات

کلیدها در فایل‌های محلی `.orca-runs/private/apis/` با مجوز محدود تا حد پشتیبانی سیستم‌عامل ذخیره می‌شوند. این فایل‌ها متن ساده‌اند، نه خزانهٔ رمزگذاری‌شده. API تنظیمات فقط `has_key` برمی‌گرداند و کلید ذخیره‌شده را بازنمی‌گرداند. فیلد خالی در ویرایش به معنی حفظ کلید است؛ تغییر میزبان به ورود دوبارهٔ کلید نیاز دارد.

مقادیر حساس وارد brief، تاریخچه، audit یا کاتالوگ نمی‌شوند. مسیر خصوصی کلید و پیکربندی native برای ورودی/خروجی وظایف و دانلود artifact مجاز نیست. کلیدهای شناخته‌شده برای حذف از متن‌های redacted ثبت می‌شوند. این کنترل‌ها جایگزین مجوزهای ابزارِ عامل و sandbox سیستم‌عامل نیستند.

برای اتصال به native، تنها provider اختصاصی این مدل در `.opencode/opencode.json` ساخته می‌شود. فایل شامل ارجاع به فایل کلید است؛ خود کلید در آن نوشته نمی‌شود. هر دو مسیر از گیت کنار گذاشته شده‌اند. تنظیمات دیگر فایل حفظ می‌شوند؛ JSON نامعتبر یا provider دست‌کاری‌شده خارج برنامه بازنویسی نمی‌شود. فایل‌های root/global OpenCode تغییر نمی‌کنند. شکل provider با نسخهٔ نصب‌شدهٔ OpenCode 1 یا 2 انتخاب می‌شود؛ برنامه نصب یا ارتقا انجام نمی‌دهد.

تغییر یا حذف اتصال هنگام وجود worker فعال مسدود است. پس از ویرایش، آزمون قبلی باطل می‌شود. حذف اتصال فایل‌های کلید همان اتصال و provider متعلق به آن را پاک می‌کند؛ برنامه‌های ذخیره‌شدهٔ وابسته باید مدل دیگری انتخاب کنند.

## محدودیت‌ها و پذیرش

- Base URL باید HTTPS روی پورت ۴۴۳ با میزبان عمومی باشد؛ URL حاوی نام کاربری، کلید، query یا fragment پذیرفته نمی‌شود. آزمون redirect را دنبال نمی‌کند و خطای خام پروایدر را بازنمی‌گرداند.
- هزینه و سهمیه همیشه در نبود شاهد `unknown` هستند. API شخصی با برچسب «رایگان تأییدشده» نمایش داده نمی‌شود.
- بودجهٔ context و خروجی انتخاب کاربر است، نه ادعای ظرفیت واقعی مدل. مقدارها باید با محدودیت مدل شما سازگار باشند.
- موفقیت آزمون اتصال و کشف کاتالوگ، پذیرش کامل مأموریت روی ویندوز نیست. معیار نهایی، تحویل فایل و بازرسی یک مأموریت واقعی است.

منابع تنظیم native: [OpenCode Config](https://opencode.ai/docs/config/)، [Providers](https://opencode.ai/docs/providers/)، [تفاوت نسخه‌های ۱ و ۲](https://opencode.ai/docs/migrate-v1/).
